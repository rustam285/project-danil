# Med Tracker

Android-приложение для учёта льготного лекарственного обеспечения пациентов: база пациентов, назначения с нормами выдачи, автоматический расчёт даты «обеспечен до», фото рецептов с офлайн-распознаванием, уведомления и выгрузка документов Word.

> Заказчик: Данил (фельдшер детской поликлиники, г. Южноуральск). Полностью офлайн: данные хранятся только на устройстве, разрешение `INTERNET` не запрашивается.

## Установка

1. Откройте раздел [Releases](https://github.com/rustam285/project-danil/releases).
2. Скачайте APK последнего релиза.
3. На телефоне разрешите установку из неизвестных источников и установите APK.
4. После установки включите для надёжных уведомлений (Xiaomi/HyperOS): Настройки → Приложения → Med Tracker → Автозапуск: ВКЛ; Экономия заряда: «Без ограничений». Эта же инструкция есть в настройках приложения.

**Важно:** обновления ставятся поверх (одна и та же подпись). Не удаляйте приложение — данные хранятся только на устройстве.

## Ключевые возможности

- Пациенты, назначения, нормы выдачи (шт/день, шт/мес, шт/год, раз в N дней, МЕ/сутки, «без расчёта срока»); история норм сохраняется.
- Автоматический расчёт «обеспечен до» точными дробями; эталонные сценарии Приложения А ТЗ покрыты юнит-тестами (`SupplyEngineTest`).
- Журнал выдач: ввод упаковками и штуками одновременно, пересчёт на лету, правка/удаление с полным пересчётом.
- Вкладка «Срочное»: закончилось / заканчивается / рецепты на исходе срока.
- Рецепты: фото с камеры/галереи (сжатие до 1600 px, JPEG 80), офлайн-OCR (Tesseract, rus+eng в APK), черновик полей с подтверждением человеком.
- Документы Word: «План диспансерного наблюдения» по пациенту и «Сводная потребность» — генерируются как OOXML напрямую, открываются в Word и WPS.
- Резервные копии: полная (`.mtbackup`) + быстрые (`.mtdelta`) в выбранный каталог, восстановление со страховой копией.
- Ежедневное сводное push-уведомление (AlarmManager exact + WorkManager как запасной механизм).

## Формат резервных копий (п. 9.6)

Контейнер — ZIP:

```
manifest.json   # schemaVersion, appVersion, type FULL|DELTA, fullId, parentFullId, seq,
                # createdAt, counts, checksums (SHA-256 файлов контейнера)
db.json         # база в человекочитаемом JSON: patients, drugs, prescriptions,
                # norms, issues, rxs, tombstones
photos/*        # фото рецептов (JPEG ≤1600 px)
```

- Даты в JSON — `epochDay` (дни) и `epochMillis` (метки времени).
- Быстрая копия содержит только записи с `updatedAt` позже последней полной + tombstones + новые фото; применима только к своей полной копии (`parentFullId`).
- **Копии не шифруются — храните их в надёжном месте.**

## Сборка для разработчика

```bash
./gradlew assembleDebug      # отладочный APK
./gradlew testDebugUnitTest  # юнит-тесты расчёта (Приложение А)
./gradlew assembleRelease    # релизный APK (подпись — см. ниже)
```

Требуется JDK 17+, Android SDK 35. `local.properties` → `sdk.dir=...`.

### Подпись релизов

Подпись постоянным keystore обязательна (обновление поверх установленного). Файл ключа **никогда не коммитится**; локально используется `keystore.properties` (в `.gitignore`):

```properties
storeFile=E:/Danil/keystore/release.keystore
storePassword=...
keyAlias=medtracker
keyPassword=...
```

CI подписывает релизы через секреты `KEYSTORE_BASE64` (файл в base64), `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.

## CI

`.github/workflows/release.yml`: на каждый пуш — юнит-тесты и сборка (артефакт APK); на тег `v*` — подписанный релизный APK в GitHub Releases. `versionCode` вычисляется из тега (`v1.2.3` → 10203) или номера запуска.

## Правила репозитория

- **Запрещено** помещать реальные данные пациентов, фото реальных рецептов и рабочие файлы заказчика — ни в коде, тестах, ни в документации. Тестовые данные — только вымышленные (Приложение Б ТЗ).
- `.gitignore` исключает `*.mtbackup`, `*.mtdelta`, keystore-файлы и локальные экспорты.

## Стек

Kotlin 2.0, Jetpack Compose (Material 3), Room, DataStore, AlarmManager + WorkManager, CameraX, Tesseract4Android (rus+eng fast), kotlinx.serialization, прямая сборка OOXML (без Apache POI/docx4j).

## Отступления от Приложения В (с обоснованием)

- Удаления хранятся физически (hard delete) + отдельная таблица `tombstones` вместо флага `deleted` на каждой сущности: так копии-дельты получают tombstones напрямую (п. 9.8), а списки не фильтруют «мусор».
- У `Drug` добавлено необязательное поле `pieceNounForms` («картридж/картриджа/картриджей») для человеческих формулировок в документах Word («10 картриджей в месяц», как в текущих файлах заказчика).
